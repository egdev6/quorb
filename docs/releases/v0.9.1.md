# Quorb 0.9.1 — Primera release para Linux / First Linux release

## Español

Instalad Quorb en Linux con un `.deb` o un `.AppImage`, y vuestras API keys
siguen ahí después de reiniciar.

### Nuevo

- Primera release pública para Linux: [`.deb` para Debian y Ubuntu](https://github.com/egdev6/quorb/releases/download/v0.9.1/Quorb_0.9.1_amd64.deb)
  y [`.AppImage` para el resto de distribuciones](https://github.com/egdev6/quorb/releases/download/v0.9.1/Quorb_0.9.1_amd64.AppImage),
  cada uno con su checksum SHA-256. Se construyen desde el mismo commit que el
  resto de la release y se verifican en un Ubuntu 22.04 limpio antes de
  publicarse.

### Corregido

- En Linux, las API keys y la sesión de NaN ya no se pierden al reiniciar. Se
  guardan en el llavero del escritorio (Secret Service: GNOME Keyring o
  KWallet). Las que guardó una versión anterior se copian solas al llavero la
  primera vez que Quorb las lee, siempre que sea antes de reiniciar; si ya
  reiniciasteis, volved a introducirlas una vez en Ajustes.

### Importante e instalación

- Disponible para [Windows x64 (EXE)](https://github.com/egdev6/quorb/releases/download/v0.9.1/Quorb_0.9.1_x64-setup.exe),
  [macOS 15+ con Apple Silicon, M1 o posterior (DMG)](https://github.com/egdev6/quorb/releases/download/v0.9.1/Quorb_0.9.1_aarch64.dmg)
  y Linux x64 (`.deb` y `.AppImage`). No hay descarga para Mac Intel.
- Windows y macOS no cambian respecto a 0.9.0.
- Linux necesita un Secret Service en ejecución (GNOME Keyring o KWallet) para
  guardar las credenciales. Si no hay ninguno, Quorb muestra un error al
  guardar y no las escribe en texto plano.
- Recomendamos el `.deb` en Debian y Ubuntu. El `.AppImage` necesita FUSE
  (`libfuse2`) y puede no montarse en algunos escritorios, por ejemplo con
  AppImageLauncher instalado; en ese caso usad el `.deb` o extraed el AppImage.
  Detalles en [la guía de Linux](../build-linux.md).
- Las actualizaciones en Linux y macOS son manuales: descargad la nueva
  versión desde la release. Windows se actualiza solo.
- Si el llavero del escritorio está bloqueado, puede pedir desbloquearlo; si
  cancelás el aviso, puede volver a aparecer en la siguiente actualización de
  datos.
- El DMG de macOS está firmado con Developer ID y notarizado por Apple; la GUI
  en un Mac real sigue pendiente en [#118](https://github.com/egdev6/quorb/issues/118).
  En Windows, la firma del updater no es Authenticode: puede aparecer
  SmartScreen. No desactivéis las protecciones del sistema para instalar.

### Gracias / Thanks

- @sosan — documentación del soporte de Linux y diagnóstico del AppImage en
  un escritorio real (#292), incluida la medición del llavero que llevó a
  corregir la persistencia de las credenciales.

## English

Install Quorb on Linux with a `.deb` or an `.AppImage`, and keep your API keys
after a reboot.

### New

- First public Linux release: [`.deb` for Debian and Ubuntu](https://github.com/egdev6/quorb/releases/download/v0.9.1/Quorb_0.9.1_amd64.deb)
  and [`.AppImage` for other distributions](https://github.com/egdev6/quorb/releases/download/v0.9.1/Quorb_0.9.1_amd64.AppImage),
  each with its SHA-256 checksum. They are built from the same commit as the
  rest of the release and verified on a clean Ubuntu 22.04 before publishing.

### Fixed

- On Linux, API keys and the NaN session are no longer lost on reboot. They
  are stored in the desktop keyring (Secret Service: GNOME Keyring or KWallet).
  Keys saved by an earlier version are copied into the keyring the first time
  Quorb reads them, as long as that happens before a reboot; if you already
  rebooted, enter them once more in Settings.

### Important and installation

- Available for [Windows x64 (EXE)](https://github.com/egdev6/quorb/releases/download/v0.9.1/Quorb_0.9.1_x64-setup.exe),
  [macOS 15+ on Apple Silicon, M1 or later (DMG)](https://github.com/egdev6/quorb/releases/download/v0.9.1/Quorb_0.9.1_aarch64.dmg)
  and Linux x64 (`.deb` and `.AppImage`). There is no Intel Mac download.
- Windows and macOS are unchanged from 0.9.0.
- Linux needs a running Secret Service (GNOME Keyring or KWallet) to store
  credentials. Without one, Quorb shows an error when saving and never writes
  them in plain text.
- We recommend the `.deb` on Debian and Ubuntu. The `.AppImage` needs FUSE
  (`libfuse2`) and may fail to mount on some desktops, for example with
  AppImageLauncher installed; in that case use the `.deb` or extract the
  AppImage. Details in [the Linux guide](../build-linux.md).
- Linux and macOS updates are manual: download the new version from the
  release. Windows updates itself.
- If the desktop keyring is locked, it may ask you to unlock it; if you dismiss
  the prompt, it may come back on the next data refresh.
- The macOS DMG is Developer ID signed and Apple notarized; GUI checks on a
  real Mac remain pending in [#118](https://github.com/egdev6/quorb/issues/118).
  On Windows, updater signing is not Authenticode: SmartScreen may appear. Do
  not disable system protections to install.

### Gracias / Thanks

- @sosan — Linux support documentation and AppImage diagnosis on a real
  desktop (#292), including the keyring measurement that led to fixing
  credential persistence.
